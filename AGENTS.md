# Правила: Objectno

- Начинать с STATUS.md и docs/decisions.md. Цель — полезное приложение и проверяемое портфолио, с восстановлением навыков Михаила.
- До реализации интерфейса определить сценарии и дизайн-систему. Перед UI-изменениями читать docs/design-system.md и design.md, затем существующий код.
- Предложения не считать утверждёнными решениями. Вопросы по брифу и учебные задания задавать по одному.
- Переиспользовать токены и компоненты, стандартные виджеты настраивать темой. Не добавлять зависимость или слой без конкретной необходимости.
- Структура приложения определена в docs/decisions/001-project-structure.md. Общий design_system не зависит от features.
- Документацию сверять с установленной версией; проверять важные сценарии и визуальные состояния. Не объявлять спецификацию реализованным и протестированным кодом.
- Обновлять STATUS.md после этапа; значимые решения и причины — docs/decisions.md и ADR в docs/decisions/. Коммиты отражают реальную работу.
- Не переносить личные данные из ../Работа/. Отдельный Git уже создан; перед первой публичной отправкой выбрать лицензию и проверить состав файлов.

- Git приложения независимый: команды выполнять из Objectno или через git -C Objectno. Следовать docs/releases.md, обновлять CHANGELOG.md для заметных завершённых изменений; VERSION менять при подготовке версии, не на каждом коммите.
- Если нужен сервер, язык — Go (ADR-002). Не создавать сервер без продуктовой необходимости.
