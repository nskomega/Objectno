# Предложение: открытое приложение «Объектно»
Статус: идея для обсуждения, разработка и публикация ещё не начаты.

## Назначение
Локальный журнал замечаний при осмотре квартиры или объекта: запись → помещение → описание → фото → статус. Использовать инженерный опыт Михаила и показать мобильную разработку на прикладном примере.

## Минимальная версия
- Создание объекта и замечаний.
- Фото из камеры или галереи; хранение в каталоге приложения.
- Статусы «Открыто / Исправлено», фильтрация.
- Локальная база, сохранение после перезапуска, работа без сети.
- Простой экспорт отчёта для передачи другому человеку.

Исключить из первой версии backend, регистрацию, совместную работу и автоматическое распознавание. Конкретные пакеты и архитектуру выбрать после практической диагностики и проверки документации.

## Как сделать доказательство навыков
Михаил самостоятельно пишет и объясняет ключевую часть. В README честно обозначать использование ИИ и свой вклад. Агент помогает планировать, разбирать и проверять. Важны понятная модель состояния, жизненный цикл ресурсов, несколько тестов реальных сценариев, обработка ошибок и воспроизводимый запуск.
Открытый код с выбранной лицензией, демоданные без персональных данных, скриншоты, короткая демонстрация, список известных ограничений. Для магазинов — политика конфиденциальности, корректные декларации данных/разрешений, стабильная сборка и материалы карточки. Публичный репозиторий без лицензии сам по себе не означает open source.

## Срок и ограничения
Ориентир: 2–3 недели до готовой к тестированию минимальной версии, зависит от самостоятельной работы и объёма экспорта. Срок проверки магазинами не обещать. Поиск вакансий продолжать параллельно. Установки и трудоустройство не гарантированы.
Готовность developer-аккаунтов и доступ к публикации проверить перед релизом.
Для личных Google Play аккаунтов, созданных после 13.11.2023, может применяться обязательный закрытый тест: минимум 12 тестировщиков непрерывно 14 дней перед запросом production-доступа. Уточнить дату и тип аккаунта перед планированием релиза.
Apple проверяет полезность и достаточную функциональность (в том числе 4.2), приватность и качество. Релиз не автоматический.

## Следующий шаг
Завершить небольшую самостоятельную практику и согласовать назначение приложения, затем разбить на задачи. Не начинать большой проект вместо проверки навыков и откликов.

## Уточнение цели
Михаил подтвердил необходимость живого GitHub, открытого кода и приложения в магазинах. Рабочее предложение — «Объектно»; название и детали продукта пока не согласованы. Активность отражает реальную работу: небольшие содержательные коммиты, задачи, исправления, релизы. Не создавать пустые коммиты и не имитировать историю. Ключевое условие — Михаил может объяснить код и самостоятельно изменить основные сценарии. Оценку синтаксиса по памяти заменить практикой с документацией.

Сначала вертикальный сценарий «создать замечание → увидеть в списке → изменить статус → сохранить после перезапуска», затем фото и экспорт. Установки не считать главным критерием успеха портфолио. Не публиковать личные материалы поиска работы вместе с кодом приложения: для приложения потребуется отдельный публичный репозиторий.

## Новая гипотеза развития
Михаил предложил анализ фотографии вместе с пожеланием заказчика, подбор материалов и последующую партнёрскую монетизацию. Подробности — [помощник по ремонту](repair-assistant.md). Предложение первой локальной версии выше остаётся предварительным; новый сценарий может изменить приоритеты после брифа.
