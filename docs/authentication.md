# Регистрация, вход и сессии
Статус: Go API реализован локально и проверен тестами; Flutter-клиент и production-размещение ещё не подключены. Контракт и ограничения — ../server/README.md. Ниже требования ко всему сценарию, не заявление об их полном выполнении. Backend — Go.

- Предлагаемый первый способ: email + пароль. Подтверждение email и восстановление требуют настроенной доставки писем; не имитировать их локальными уведомлениями.
- Пароли хешируются проверенной библиотекой с солью и соответствующими параметрами; не логируются и не сохраняются в приложении.
- Короткоживущий подписанный access JWT; сервер проверяет алгоритм из разрешённого списка, подпись, issuer, audience, exp и права на ресурс. JWT не шифрует содержимое: не помещать в payload пароли или приватные данные.
- Refresh token — случайный непрозрачный секрет, на сервере хранить его хеш. Ротация и отзыв сессии при выходе/повторном использовании, срок жизни и одновременное обновление проработать и проверить.
- На мобильном клиенте refresh token хранить в системном защищённом хранилище, access token по возможности в памяти; не в shared_preferences или открытом файле. Web-демо не использует мобильную схему хранения токенов автоматически.
- Только HTTPS в production; секреты из конфигурации сервера, не из репозитория/клиента. Ограничение частоты запросов входа/регистрации и безопасные сообщения об ошибках.
- Авторизация на каждой операции с объектом/замечанием: пользователь не может читать/менять чужие данные по известному id. Сам факт валидного JWT не даёт доступ ко всем записям.
- Удаление аккаунта из приложения с удалением связанных данных/фото и отзывом сессий. Публичная политика данных и работающий контакт поддержки до магазинного релиза.
- Проверки: неверный/истёкший токен, чужой объект, повторный refresh, выход, повторный вход, удаление, сетевые ошибки и сохранность локального черновика.

## Клиентский слой dev.6
HTTP-клиент и контроллер реализованы и проверены модульно; UI ещё не подключён. API_BASE_URL без значения отключает API. Release допускает только HTTPS; локальный HTTP — для отладки. Access token живёт в памяти, refresh — в системном secure storage (web: только память). Одновременные refresh объединяются, чтобы не вызвать отзыв из-за повторного использования токена. Таймаут запроса 20 секунд, ответ ограничен 64 КиБ при чтении.

Выход требует успешного серверного отзыва; при сетевой ошибке сессия сохраняется и UI должен предложить повторить. Удаление аккаунта сначала подтверждается сервером, затем удаляет локальный раздел текущего пользователя и очищает сессию. Разделы Sembast — логическая изоляция в приложении, не шифрование базы. Пока нет синхронизации, записи остаются только на устройстве. Проверка secure storage и жизненного цикла на настоящих устройствах ещё обязательна.

## UI dev.7
Экран аккаунта подключён, локализован на восемь языков, доступен через иконку аккаунта. Смена identity создаёт новый Navigator и раздел журнала. Без API_BASE_URL вход отключён с объяснением, гостевой режим доступен. Тесты UI используют mock HTTP; это не проверка публичного API или Keychain на устройстве.

## Anonymous analysis sessions
POST /v1/auth/guest issues the same revocable access/rotating refresh session for an explicitly anonymous user, without email or password. Endpoint is behind the existing per-IP auth rate limiter. Guest sessions are created only when accessToken is requested, not on every app start. Client guest identity stays mapped to the original local guest store; signing in to a registered account remains a separate scope. This does not synchronize local objects or store photos on the auth server.
