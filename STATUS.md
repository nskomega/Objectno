# Состояние Objectno

Обновлено: 08.11.2026. Исходники: **0.1.0-dev.47**. Последние обычные артефакты: **dev.44**, iOS Simulator и Android debug APK. На пользовательском iPhone остаётся сборка **20**.

## Цель
Первый выпуск в App Store и Google Play, затем ежедневное развитие. **Публикаций нет, цель не выполнена.** Требования: [product-proposal.md](docs/product-proposal.md). Ванная, кухня, спальня и другие помещения; санузел — пример.

## Реализовано
- Единый объект ремонта: исходное фото и пожелания, предложения, ход работ и результат в общей истории. Прежние замечания и фото сохранены.
- Локальная БД Sembast с разделением гостя и аккаунтов; профиль, компактные вкладки, две темы, восемь языков, системный масштаб текста. Синхронизации нет.
- Go API: регистрация, вход, гостевые сессии, JWT/refresh с ротацией, logout, удаление аккаунта, bbolt. Нативные токены — secure storage; web — память.
- Локальный анализ: Go → MLX на Mac → Qwen3-VL-4B-Instruct-4bit. Без платных API. Это интеграция открытых весов, не обучение собственной модели. [Запуск](docs/local-analysis.md).
- Анализ каждого исходного фото сохраняет предложение с источником и данными модели. Неподходящая сцена не получает плана. Ответ — предварительный черновик.
- Прямоугольные обмеры и проёмы с координатами; запрещены пересечения/выход за стену. Площадь нетто, пропорциональный план с номерами стен и выделенными проёмами.
- Расчёт по конкретному продукту: поверхности, норма/источник, единицы, фасовка, слои и запас. Данные продукта вводит пользователь, каталога нет. История сохраняет копию обмеров и все входные данные. [Формула](docs/quantity-calculation.md).

## Проверено
- **70 Flutter widget/unit-тестов и 1 отдельный нативный integration test**, статический анализ без замечаний. Включены 3x текста в обеих темах, аккаунты, проёмы и форма расчёта с возвратом в историю.
- **12 Python-тестов**; Go race-тесты и vet прошли.
- Android debug APK и iOS Simulator **44** собраны; нативные проверки ниже относятся к указанным сборкам. Это не магазинные артефакты.
- Симулятор: реальное фото кухни → модель → предложение → перезапуск → предложение осталось. Цветы отклонены. Проверено на промежуточной сборке 28 с подписью, исправленной в dev.29.
- Симулятор, сборка 37: проём 1×2 м сохранён, площадь стен 25 → 23 м². По условной норме 100 мл/м², двум слоям и запасу 10% сохранён расчёт 5060 мл / 3 упаковки по 2500 мл. После полного перезапуска и проём, и расчёт остались. Это тестовые нормы, не рекомендация продукта.
- Рендеры схемы при 3x просмотрены в обеих темах: output/preview/measured-plan-*-3x.png. Arial использован только для читаемого тестового рендера; шрифт приложения не менялся.
- iPhone: владелец подтвердил старое фото и новый объект с исходным фото на сборке 20. Камера/сохранность после перезапуска ранее подтверждены на 14.

## Следующие шаги и ограничения
1. Нативный integration test сборки 44 прошёл: реальная модель, выбор lighting, результат в истории, открытие БД заново и восстановление Keychain. Нативный снимок просмотрен; Mac блокировка больше не мешает этому сценарию. Полный перезапуск процесса/камера этим тестом не покрыты. Инструкция: docs/native-integration.md.
2. Prompt 10: ограниченный словарь предметов с переводами, явные категории работ. Реальные API-проверки ванной/спальни/кухни только со светом прошли, скриншот с клавиатурой отклонён. Наблюдения новых двух комнат соответствуют видимым крупным предметам, но набор слишком мал для принятия качества. Flutter 42 передаёт категории; положительный нативный запрос с выбором проверен интеграционным тестом в dev.44. Манифест: ml/evaluation/.
3. Речь, генерация визуала ремонта, раскладка плитки, реальные товары/цены/наличие, инженерные трассы и заказ исполнителей **не реализованы**.
4. Для магазинов: публичный HTTPS API и размещение вычислений, восстановление доступа/подтверждение email, подпись/идентификаторы, политика данных и карточки. reg.ru Хост-А не подтверждён как среда для Go/MLX; локальный Mac API не общедоступный сервис.
5. Для исходников выбрана MIT (dev.45), состав истории проверен. Создан публичный https://github.com/nskomega/Objectno, origin подключён, вся история отправлена в main 08.11.2026. Личные сведения соседнего направления не публиковать.
